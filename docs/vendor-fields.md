# What each vendor sends, and where it goes

One row per field this library has looked at, with what happened to it and the test that proves
it. The point of the table is the **omissions**: a field with no row is a field nobody checked, and
a field with a row that says `omit` is a decision somebody can argue with. "The current interface
has no card for it" is not a reason and never appears below.

Read it alongside [`contracts.md`](contracts.md), which says what the destinations mean, and the
per-harness guides, which say why each surface is driven the way it is.

## How to read a row

| Column          | What it says                                                                                       |
| --------------- | -------------------------------------------------------------------------------------------------- |
| **Vendor**      | The harness and the version the row was checked against — a pin, not "latest"                      |
| **Field**       | The native name, spelled exactly as it appears on the wire                                         |
| **Enabled**     | `runtime` where the pinned build sends it by default, `experimental` where the vendor labels it so |
| **Destination** | The neutral type it becomes, or `—`                                                                |
| **Disposition** | `preserve`, `redact`, `omit` or `refuse`                                                           |
| **Reason**      | Why, in one clause. Every `omit` and `refuse` has one                                              |
| **Evidence**    | The test that fails if the row stops being true                                                    |

`refuse` is distinct from `omit`: an omitted field is one this library read and did not carry, and a
refused one is a request it answered "no" to. Only requests can be refused.

## What is missing from this table

Two things, and both are gaps rather than decisions:

- **Claude's `TodoWrite`.** It is where a plan's steps live, and it is the one place Claude is
  behind the other two harnesses. Unblocking it needs `mea capture` to record a turn that drives it
  at the pin, not a guess at its input keys.
- **Per-variant Codex item schemas.** The vendored inventory flattens every item family's properties
  into one union, which is enough to catch a rename and not enough to say which family owns a field.
  A subagent's thread id is unmappable for that reason alone.
